# 정우 · 서하 모바일 청첩장 — 수정 패키지 v2

기존 `simsulbo99/wedding-invitation`을 기준으로 작성했습니다. **아직 GitHub/Google Apps Script에 자동 반영된 것은 아닙니다.**

## 주요 변경

1. The Day의 WHERE 아래에 `DRESS CODE` 행 추가.
2. Atlas 버튼 `Photo Album.`으로 변경: 기존 청첩장과 같은 디스플레이 폰트 사용, `Album.`에 미세한 이탤릭.
3. RSVP 항목별 위아래 여백 보정. RSVP의 제출 로직과 기존 데이터에는 영향 없음.
4. 방명록 왼쪽에 사진 이벤트 안내 추가.
5. 체크박스 동의 UI 삭제. **대신** '등록하신 이름·메시지·사진은 청첩장에서 공개됩니다'라는 안내문을 유지.
6. 사진 최대 **10장, 선택한 원본의 합계 100MB**. 업로드는 각 사진을 JPEG로 최대 약 675KB 수준으로 압축하고 **한 장씩** Apps Script로 전송. 100MB 원본이 100MB 그대로 Drive에 저장되는 기능은 아닙니다. 원본 화질이 필요한 사진 공모전이라면 별도 전송 방식을 고려해야 합니다.
7. 갤러리 카드에 대표사진 / `N PHOTOS` 겹친 사진 장식 / 이전·다음 버튼 및 스와이프 추가.
8. `Messages of Love.` 제목과 Atlas 영문 대제목에 청첩장과 같은 `Relationship of Melodrame` 폰트 적용. Atlas의 한글/기능 버튼은 원래의 읽기 쉬운 폰트 유지.
9. 갤러리는 한 페이지 5개, 숫자 페이지 이동으로 전환.
10. 업로드 중이던 사진이 전부 저장되기 전에는 글을 공개하지 않음. 기존 단일사진 게시물은 보존.

## 1단계: Google Apps Script — 반드시 먼저

1. 지금 실제로 사용 중인 구글 스프레드시트 → **확장 프로그램 → Apps Script**.
2. 기존 `Code.gs`를 **반드시 백업**하세요. 기존 코드를 따로 수정한 이력이 있다면 이번 `Code.gs`와 병합해야 합니다. 패키지의 코드는 이전에 전달했던 RSVP + 공개 방명록 서버 버전을 바탕으로 만든 것입니다.
3. `Code.gs` 전체를 교체합니다. `doPost`/`doGet` 함수가 중복되지 않도록 기존 코드를 완전히 교체하거나 수동 병합하세요.
4. 함수 드롭다운에서 `setupGuestbook`을 1회 실행합니다. **기존 GUESTBOOK 데이터는 삭제되지 않습니다.** 기존 GUESTBOOK 시트에 I열 `사진수`, J열 `사진 ID 목록(JSON)`이 추가되고, 별도 `GUESTBOOK_PHOTOS` 시트가 생성됩니다. 사진용 Drive 폴더는 기존 ID를 재사용합니다.
5. `배포 → 배포 관리 → 연필(수정) → 버전: 새 버전 → 배포`. 새 배포를 만들기보다 기존 배포를 업데이트하면 **이전에 쓰던 `/exec` URL이 유지**됩니다. 실행 사용자 **나**, 접근 **모든 사용자**인지 확인하세요.
6. 웹 앱 URL을 바꿨다면 `guestbook.js`와 기존 `rsvp.js` 상단의 `ENDPOINT`를 함께 변경합니다.

### 시트 운영

- `GUESTBOOK`: E열 = 대표사진 ID, F열 = 공개상태 (`공개` / `숨김` / 일시적인 `업로드중`), I열 = 사진수, J열 = 사진 ID 목록. 기존 A~H열은 보존합니다.
- `GUESTBOOK_PHOTOS`: 게시물 ID / 순서(0부터) / Drive 파일 ID / 요청 ID / 저장일. **사진 간 연결 정보이므로 임의 삭제·수정 금지.**
- `업로드중`은 사진 10장 중 일부를 보내는 과정 등에서 아직 공개되지 않은 건입니다. 모바일 네트워크가 끊겨 전송 실패가 발생하면 남을 수 있습니다. 개인정보와 Drive 파일을 함께 확인한 뒤 정리할 수 있습니다.
- 글 숨김은 `GUESTBOOK` F열을 `숨김`으로 바꿉니다. **사진 링크 자체가 비공개로 바뀌지는 않습니다.** Drive 공유도 해제해야 완전 비공개가 됩니다.
- 이미 저장된 한 장짜리 게시물은 이전 E열 ID를 통해 계속 노출됩니다.

## 반드시 테스트할 시나리오

1. 이전 메시지/이전 단일 사진이 그대로 표시되는지.
2. 사진 없이 새 글 등록 → GUESTBOOK에 `공개`, 총 사진 0장.
3. 사진 2~3장 등록 → `GUESTBOOK_PHOTOS`에 순서별로 기록, 카드에서 이전/다음 이동.
4. 사진 10장 등록 → 진행 메시지 `1 / 10 ... 10 / 10`, 카드 `10 PHOTOS`, 다음/이전/스와이프.
5. 기존 방명록 글 6개 이상일 때 1페이지 5개/2페이지 나머지, 페이지 번호 확인.
6. Google Sheets F열을 `숨김`으로 변경 → 페이지 새로고침 시 카드 삭제.
7. RSVP 기존 신규·수정 제출, iOS Safari·카카오톡·Chrome 모바일에서 확인.

## 서비스 한계와 주의사항

- **100MB는 선택 가능한 원본 파일 합산 한도**이지 100MB 원본을 무손실 보관한다는 뜻이 아닙니다. Google Apps Script 단일 POST 크기·실행시간 한계 때문에 각각 압축한 작은 JPEG를 별도의 요청으로 보냅니다. 원본 화질이 선물 선정에 필요한 경우 이 설계는 부적합할 수 있습니다.
- 사진 10장 전송은 네트워크와 Google Apps Script 할당량에 따라 느릴 수 있습니다. 전송이 확인되지 않으면 자동으로 공개하지 않으며, `업로드중` 기록이 남을 수 있습니다. 다시 전송하면 중복 게시물이 생성될 수 있으니 관리 시트에서 먼저 확인하세요.
- Android/iOS 브라우저마다 HEIC 지원이 달라 일부 HEIC 사진은 JPG로 변환해야 합니다.
- 동의 체크박스는 요청대로 제거했지만 **공개 안내문은 유지**했습니다. 개인정보 및 사진 공개에 관한 고지·동의의 충분성은 별도로 검토하세요.
- 누구나 글을 게시할 수 있는 공개 방명록이므로 도배/부적절한 내용은 운영자가 Google Sheets에서 숨김 처리해야 합니다. 이 구현은 로그인, CAPTCHA, 자동 차단 기능이 없습니다.
- 프런트엔드와 Apps Script 문법/구조 검사는 했지만, 실제 Google 계정의 `DriveApp`과 실기기 통합 업로드는 실행할 수 없었으므로 배포 전 테스트해야 합니다.
